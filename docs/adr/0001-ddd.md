# ADR 0001: Adoption of Domain-Driven Design (DDD) Architecture

**Status:** Accepted  
**Date:** July 26, 2026  

## Context
LeadPilot AI CRM requires a scalable architecture to manage real estate CRM entities (Leads, Deals, Contacts, Tasks, Properties) without coupling business logic to specific frontend frameworks or database SDKs.

## Decision
We adopt Domain-Driven Design (DDD) principles:
- **Entities & Value Objects:** Located under `src/domain/<domain>/types.ts` as pure TypeScript interfaces with zero framework dependencies.
- **Workflow Rules:** Isolated under `src/domain/<domain>/workflow/` (e.g. `TaskWorkflowRules.ts`).
- **Repositories:** Abstract interfaces under `src/contracts/` decoupling application logic from infrastructure.

## Consequences
- Business logic is portable, testable, and isolated.
- UI components consume domain entities without raw SQL or Supabase-specific types.
